# TunerNook README Refresh

## Intent

Make the public project page sound like its creator and help potential users
understand what TunerNook does, what makes its workflow distinctive, what has
actually been tested, and how they can help improve it.

## Content

- Say plainly that this is a personal project built with AI-assisted
  “vibe-coding”, and that the author wants others to use, improve, and share it.
- Describe concrete workflow choices without unsupported claims of superiority:
  explicit/no-overwrite edits, visible raw and engineering values, persistent
  workspaces, heuristic Map Finder, synchronized tables and 3D surfaces, and
  user-controlled NookLink proposals.
- Report the verified Beta 1 test results with a clear caveat that tests reduce
  risk but cannot prove correctness or vehicle safety.
- Prominently warn about beta status, calibration validation, backups, vehicle
  damage risk, and the author's no-warranty/no-responsibility position.
- Welcome issue reports, feedback, and contributions. Keep the MIT license.
- Preserve practical build instructions and link to the deeper protocol/setup
  documentation instead of leading with long protocol details.

## Screenshots

Copy only the user's two explicitly approved root screenshots, byte-for-byte,
into `docs/screenshots/` under descriptive names. Embed both in the README with
meaningful alt text. Do not include other ShareX captures or calibration files.
