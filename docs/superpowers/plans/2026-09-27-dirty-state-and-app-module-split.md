# Dirty-State and App Module Split Implementation Plan

> **For agentic workers:** Execute inline, task by task. Keep the behavior fix and the behavior-neutral extraction in separate tasks and snapshots.

**Goal:** Make dirty checks constant time and begin a carefully staged split of the oversized app source.

**Architecture:** `BinDocument` maintains an exact changed-byte count at committed state transitions, making `is_dirty` and `changed_byte_count` O(1). Then move the cohesive table-coloring/sweep helpers to `table_colors.rs`, retaining the existing crate-root API and current test access.

**Tech Stack:** Rust 2021, Cargo workspace, existing `tuner-core` and `tuner-app` tests. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-27-dirty-state-and-app-module-split.md`

## Global Constraints

- Add no dependencies and do not change BIN/XDF bytes or public UI/IPC behavior.
- Preserve exact dirty-state behavior across transactions, undo, redo, abort, and return-to-original edits.
- Preserve the root API paths for `color_range_for_values` and `table_cell_fill`.
- Increment the app patch version from 0.1.4 to 0.1.5.
- This workspace has no Git metadata; keep before/after snapshots and test results in the SDD ledger.

## Review Focus

1. Repeated writes to one offset inside a single transaction are counted by their net final value, not by write count.
2. Undo and redo must transition bytes relative to the immutable original, including when a byte was already dirty before a new transaction.
3. Aborted/dropped edits and net-zero transactions leave the cached dirty count unchanged.
4. Dirty-count arithmetic must never underflow or exceed the fixed BIN length.
5. The table-color move must retain root-level public paths and preserve non-finite filtering, fixed/auto ranges, palette colors, and Sweep rendering.
